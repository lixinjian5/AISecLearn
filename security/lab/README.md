# Security Lab 靶场设计

## 设计思路

基于 Pikachu 漏洞练习平台改造和扩展，与 AISecLearn 主站通过链接跳转集成。

## 架构方案

```
┌─────────────────────────────────────┐
│          AISecLearn 主站             │
│  ┌──────────┐ ┌──────────────────┐  │
│  │ AI 导师   │ │ 代码安全分析     │  │
│  └──────────┘ └──────────────────┘  │
│  ┌──────────────────────────────┐   │
│  │ "进入靶场" → 跳转到 Lab      │   │
│  └──────────────────────────────┘   │
└──────────────┬──────────────────────┘
               │ 链接跳转
               ▼
┌─────────────────────────────────────┐
│   Docker 容器：Pikachu 靶场          │
│   端口映射：宿主机 8765 → 容器 80    │
│   与主站网络隔离，互不影响           │
└─────────────────────────────────────┘
```

## 部署方式

```bash
# 使用已有 Docker 镜像，一行命令启动
docker run -d -p 8765:80 8023/pikachu-expect:latest
```

启动后学生访问 `http://服务器IP:8765` 即可进入靶场。

## 实验关卡设计

基于 Pikachu 现有场景，为每个实验编写实验说明文档，统一格式。

### 实验文档格式

每个实验一个 Markdown 文件，格式如下：

```markdown
# 实验名称

## 难度
⭐ 入门 / ⭐⭐ 进阶 / ⭐⭐⭐ 挑战

## 实验目标
用一句话说明学生要做什么

## 背景故事
设计一个小场景，增加趣味性（可选）

## 页面入口
Pikachu 中对应的模块路径

## 操作步骤
1. 第一步
2. 第二步
3. ...

## 预期结果
学生做成功后应该看到什么

## 提示
给学生的小提示（可选）

## 答案
（仅教师查看）
```

## 与 AI 导师的联动

目前的 MVP 阶段：学生从 AISecLearn 主站跳转到 Pikachu 做题。

未来可以扩展：学生在靶场做实验遇到困难时，可以回到 AI 导师提问，AI 根据知识库内容辅导学生完成实验。
