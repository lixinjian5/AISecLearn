# AI 多模式 API 调用架构设计

> 设计目标：让平台支持多种 AI 调用模式，降低运营成本，提高系统扩展能力。

---

## 背景

AI 安全学习平台的核心功能依赖大模型 API。如果所有用户请求都走平台自己的 API Key：

> 用户越多 → API 调用越多 → 成本越高

需要设计合理的调用策略，在保证用户体验的同时控制成本。

---

## 三种调用模式

### 模式 1：游客免费体验（默认）

- 新用户无需任何配置，直接体验 AI 导师
- 每天免费额度：10 次
- 后端使用平台管理员配置的 API Key
- **目的**：降低门槛，让用户先体验产品价值

### 模式 2：用户自定义 API Key

- 免费额度用完后，提示用户绑定自己的 API Key
- 后续请求使用用户自己的 Key，平台零成本
- API Key 存储：浏览器 localStorage（当前阶段）

### 模式 3：管理员模式

- 开发/测试/演示使用
- 无限额度
- 方便调试和项目展示

---

## 技术架构

```
用户请求
    ↓
AIService（抽象层）
    ↓
判断模式：
    - 免费用户 → 平台 API
    - 自定义 Key → 用户 Key
    - 管理员 → 无限额度
    ↓
调用模型（DeepSeek / 未来可切换）
    ↓
返回结果
```

**关键原则**：业务代码不直接调用模型 API，统一走 `AIService` 抽象层。

---

## 开发优先级

| 阶段 | 内容 |
| --- | --- |
| **当前（MVP）** | AI 导师核心对话，前端直调 DeepSeek API |
| 第二阶段 | 加入用户系统 |
| 第三阶段 | 加入免费次数限制 |
| 第四阶段 | 加入用户 API Key 模式 |
| 第五阶段 | 优化模型切换（支持多模型） |

---

## 当前实现

MVP 阶段，AI 调用走 `src/services/aiService.js` 抽象层。

前端通过 `VITE_DEEPSEEK_API_KEY` 环境变量配置平台 API Key。

后续接入后端时，只需修改 `aiService.js` 的网络请求目标，业务代码无需变动。
